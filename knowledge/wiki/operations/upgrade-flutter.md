# Upgrade Flutter

A Flutter upgrade is a deliberate change, and the pins move together.[^flutter-commit] Start with `just flutter-latest` to compare the latest stable with this project.[^just-latest]

## Pins to change in one commit

| File | Value |
| ---- | ----- |
| `mise.toml` | `flutter` |
| `pubspec.yaml` | `flutter` **and** `sdk`, which is the Dart bundled with that Flutter[^pubspec] |
| `pubspec.lock` | Regenerated by `flutter pub get`[^lock] |
| `.github/workflows/ci.yml` | `flutter-version`, in all five places |
| `README.md` | The version in its first development line[^readme] |

```sh
mise install
flutter pub get
flutter analyze
flutter test
```

## What an upgrade can change quietly

- **Minimum OS on Android.** `minSdk` and `targetSdk` come from Flutter, and the spec accepts its defaults at build time.[^spec-minimum][^gradle-levels]
- **Android behaviour on tablets.** The spec's landscape constraint exists because API 36 ignores the portrait lock on wide screens, so a `targetSdk` bump can matter.[^spec-minimum]
- **`dart format` output.** CI fails on any change, so a new formatter may need a reformat commit.
- **`just setup-android`.** It parses `FlutterExtension.kt` from the Flutter checkout, and reports a clear error if that source moves.[^just-android] Run it after upgrading, or pin the levels in the justfile.

Acceptance tests do not run under `flutter test`, so let CI's emulator and simulator jobs finish before merging.
